# ADR-001: Вибір архітектурного стилю

## Статус
Прийнято

## Контекст
Expense Tracker — це REST API для обліку особистих витрат, що розробляється на Node.js та Express.js. Проєкт створюється однією особою в межах навчального курсу з дисципліни «Конструювання програмного забезпечення». Система включає автентифікацію користувачів, CRUD-операції з витратами, роботу з категоріями, аналітику та формування звітів.

Для проєкту потрібна архітектура, яка є простою у розумінні, зручною для підтримки, придатною для тестування та відповідає розміру команди і складності задачі.

## Рішення
Використовувати Layered Architecture (шарову архітектуру) з MVC-подібним поділом відповідальності, реалізованим через Express.js.

Основні шари системи:

- **Presentation Layer**: `routes/` та `controllers/` — приймання HTTP-запитів, перевірка параметрів запиту, виклик відповідних сервісів і повернення JSON-відповідей.
- **Business Logic Layer**: `services/` — реалізація бізнес-правил, обробка логіки витрат, категорій, користувачів, авторизації, аналітики та звітів.
- **Data Access Layer**: `repositories/` та `prisma/` — робота з базою даних через ORM або окремий модуль доступу до даних.
- **Database Layer**: SQLite / PostgreSQL — збереження інформації про користувачів, витрати та категорії.

## Альтернативи, що розглядалися

- **Мікросервісна архітектура**: відхилено, оскільки проєкт розробляється однією особою, а мікросервіси доцільні переважно для великих команд і складних production-систем.
- **Моноліт без чіткої шарової структури**: відхилено, оскільки змішування HTTP-обробників, бізнес-логіки та роботи з базою даних ускладнює підтримку коду.
- **Clean Architecture**: відхилено, оскільки вона є більш складною для невеликого CRUD-застосунку.

## Наслідки

+ Чіткий розподіл відповідальності між шарами системи.
+ Код легше підтримувати, тестувати та розширювати.
+ Зміна бази даних або ORM переважно впливає лише на Data Access Layer.
+ Структура проєкту зрозуміла для розробників, знайомих із Node.js, Express.js та MVC.
- Кількість файлів і папок більша, ніж у простому моноліті.
- Потрібно дотримуватися дисципліни, щоб бізнес-логіка не потрапляла в controllers або repositories.
